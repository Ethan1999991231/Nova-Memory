# 青色亚克力内存优化器设计稿

日期：2026-10-28

## 目标

制作一个 Windows 单文件 EXE 内存优化工具，界面轻巧、漂亮、易懂。用户打开后能立即看到当前内存占用，点击按钮可手动优化；开启自动优化后，程序持续检测内存负载，在超过用户设定的上限时自动执行清理。

## 已确认的产品决策

- 视觉方向：青色半透明亚克力毛玻璃。
- 优化模式：设置中提供“安全模式”和“强力模式”，用户可切换。
- 自动优化：设置中提供开关。
- 触发阈值：设置中提供可滑动调整的上限，默认 80%。
- 设置持久化：保存后写入当前用户 AppData，下次启动自动恢复，不要求用户重新设置。
- 进程范围：设置中提供普通 / 全部两种范围。
- 启动项范围：设置中提供安全管理 / 完整管理两种范围。
- 打包目标：一个可直接运行的 Windows EXE。
- 不在本期加入：账号、联网、广告。
- 本期新增系统维护功能：注册表清理、结束进程、系统启动项管理。

## 方案选择

采用 Python Tkinter + psutil + Windows 原生 API + PyInstaller。

原因是它能在保持界面可定制的同时控制 EXE 体积和启动速度。Tkinter 负责窗口和基础控件；Windows DWM API 负责亚克力/毛玻璃效果；psutil 负责读取内存和进程信息；Windows API 的 `EmptyWorkingSet` 负责整理可访问进程的工作集。

## 界面结构

### 主页

- 顶部：应用名称、当前状态徽标、设置入口。
- 中央：大号内存占用百分比，下面显示“已用 / 总内存”。
- 环形或半环形进度显示当前占用，颜色随负载从青色过渡到暖橙色。
- 主按钮：“立即优化”。执行期间显示处理中，完成后显示释放结果或可读的失败原因。
- 底部：自动优化状态、当前阈值、上次优化时间。

### 设置页

- 自动优化开关。
- 触发上限滑块：50%–95%，步进 1%，实时显示例如“上限 80%”。
- 优化模式切换：安全 / 强力。
- 保存按钮；保存后立即应用到监控器，并写入持久化配置。

### 系统维护页

- 注册表清理入口，分为安全清理和深度清理。
- 可访问的普通进程列表，支持选择后结束进程。
- 启动项列表，支持查看、启用和禁用当前用户启动项；系统级项目在需要管理员权限时提示用户。

## 行为与数据流

1. 启动时加载 `%APPDATA%\\NovaMemory\\settings.json`。
2. 如果文件不存在或内容损坏，使用默认配置：自动优化关闭、阈值 80%、安全模式。
3. 主线程每 1 秒刷新显示数据；后台监控每 5 秒读取内存占用。
4. 自动优化开启、占用率大于等于阈值、且距上次自动优化至少 60 秒时，触发一次清理。
5. 清理结束后重新读取内存，记录释放前后数值，并在主页给出结果。
6. 设置保存后，立即更新内存中的配置并覆盖 JSON 文件；重启时从该文件恢复。

## 优化策略

### 安全模式

- 只处理当前用户拥有且可访问的普通用户进程。
- 跳过当前优化器自身、系统空闲进程、系统进程、受保护进程和明显的系统关键进程。
- 不结束进程，不修改优先级，不删除文件，不清理注册表。

### 强力模式

- 在安全模式范围基础上，尝试整理更多可访问的普通后台进程工作集。
- 仍然跳过系统关键进程和当前应用自身。
- 单个进程整理失败时继续处理其他进程，并在结果中统计跳过数量。

Windows 会拒绝部分受保护进程的操作；这属于正常情况，必须被安静地跳过，不能让自动监控崩溃。

## 注册表清理

注册表清理只允许手动执行，不会被内存自动优化触发。

### 安全清理

- 扫描已知的临时项、失效路径和明确可识别的无效项。
- 执行前展示扫描结果和预计删除数量。
- 执行前自动导出待修改项到带时间戳的 `.reg` 备份文件。
- 用户点击确认后才删除；权限不足的项跳过并报告。

### 深度清理

- 扫描范围比安全清理更广，但仍跳过系统核心配置和无法可靠判断的项。
- 每次开始深度清理时重新生成一个 6 位伪随机数字。
- 对话框展示这 6 位数字，用户必须完整输入正确后才能继续。
- 每次尝试都使用新数字；取消、输入错误或窗口关闭都会中止本次操作。
- 深度清理同样必须先创建 `.reg` 备份，并先预览结果再执行。

深度清理不允许静默执行，也不允许由自动优化触发。

## 进程结束

- 仅显示当前用户可访问的普通进程。
- 系统关键进程、当前应用自身和受保护进程不可选择。
- 结束前显示选中数量和进程名称，要求用户确认。
- 单个进程拒绝结束时继续处理其他进程，并报告成功/跳过数量。

## 启动项管理

- 读取当前用户和系统级 Run 项、启动文件夹项目。
- 支持启用/禁用，不直接删除原始条目。
- 安全管理只显示当前用户启动项；完整管理额外显示系统级启动项。
- 修改前保存原始值，便于恢复。
- 系统级条目需要管理员权限时明确提示；没有权限则只读展示。

## 持久化格式

```json
{
  "auto_optimize": false,
  "threshold": 80,
  "mode": "safe",
  "process_scope": "user",
  "startup_scope": "safe"
}
```

只保存用户可配置项，避免把运行时状态写入设置文件。

## 错误处理

- 配置文件无法读取：回退默认值，并在设置页显示一次轻提示。
- 配置保存失败：保留内存中的改动，同时提示“本次运行已生效，但无法保存”。
- 单个进程没有权限：跳过并继续。
- 清理没有释放明显内存：仍显示“已完成检查”，避免承诺不确定的释放量。
- 关闭窗口时停止监控线程，避免后台线程阻止退出。
- 注册表备份失败时禁止执行对应清理。
- 深度清理验证码错误时不执行任何修改。

## 验收标准

- 启动后主页能显示真实的内存占用百分比，并持续刷新。
- 点击“立即优化”后有明确的处理中和完成反馈。
- 自动优化开关可用，关闭时不会触发自动清理。
- 滑块可调整 50%–95% 上限，保存后自动监控使用新阈值。
- 关闭并重新启动 EXE 后，自动优化开关、阈值和模式保持上次保存的值。
- 安全/强力模式可切换，清理失败的单个进程不会导致程序退出。
- 注册表安全清理和深度清理都需要预览与确认；深度清理每次都要求正确输入 6 位数字。
- 进程结束列表支持普通 / 全部范围，但不会提供系统关键进程。
- 启动项支持安全管理 / 完整管理；项目可以禁用/恢复，权限不足时不会伪装成成功。
- 可以打包为一个 Windows EXE 并启动。

## 验证计划

- 单元测试：设置默认值、JSON 保存/加载、阈值边界、模式切换。
- 行为测试：自动优化触发条件、60 秒冷却、关闭自动优化时不触发。
- 行为测试：注册表安全/深度清理的预览、备份、验证码和失败中止路径。
- 行为测试：进程范围切换、系统关键进程过滤、批量结束确认。
- 行为测试：启动项安全/完整范围切换、禁用/恢复和权限不足提示。
- 手动测试：主页刷新、按钮状态、设置页滑块和重启恢复。
- 打包验证：PyInstaller 生成的单文件 EXE 在干净启动后可打开并读写配置。
